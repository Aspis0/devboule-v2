Devboule v2 project code is distributed under Apache-2.0; see LICENSE and NOTICE.
This file is the attribution inventory for the repository state audited on 2026-08-27.
It distinguishes linked dependencies, source copied into the repository, and non-code assets.

## How this inventory was built

The Rust inventory is the complete set of 965 registry packages resolved by the workspace Cargo.toml files and Cargo.lock with all features enabled. The JavaScript inventory is the complete set of 158 package records in pnpm-lock.yaml. Direct versus transitive/build/test/optional status is derived from the workspace manifests and package.json.

Both tables are generated by `scripts/generate-third-party.mjs` from `cargo metadata` and `pnpm-lock.yaml`, between the `BEGIN GENERATED` and `END GENERATED` markers; everything outside those markers is written by hand. `node scripts/generate-third-party.mjs --check` fails when the document has drifted from the lockfiles, and CI runs it. The Rust count is 965 rather than the 972 entries in `Cargo.lock` because the seven workspace crates of this project are not third-party; the vendored `esaxx-rs` is, and is counted.

The licence column preserves the package-declared licence expression. OR and AND are not rewritten into a simpler label. The Rust metadata comes from cargo metadata; npm metadata comes from the package metadata of the exact versions pinned in pnpm-lock.yaml, read from the local install where materialized and from the exact registry package metadata for the same version otherwise. The local pnpm store still holds directories for packages the lockfile no longer references after the frontend toolchain change, so the installed tree was not used to decide which records belong in the inventory. The lockfiles remain the version and source authority.

The lockfile inventories include conditional platform packages. A package listed in the lockfile is not necessarily linked into every target artifact; on Windows, only the Windows target branches are selected. Build/test dependencies are not shipped as application runtime code.

## Copied or vendored source code

One third-party file is vendored as **data, not code**: `crates/devboule-augur/vendor/gitleaks/gitleaks.toml`, the gitleaks secret-detection rule set taken at tag v8.21.2, commit 43fae355e6fe4d99d2a7b240a224b85e2903aeb4, under the MIT licence (Copyright (c) 2019 Zachary Rice). Its LICENSE ships beside it and `VERSION` records the upstream repository, tag, commit and the date taken. No Go code is used; the TOML is parsed and the regexes compiled by our own loader.

The repository does include the third-party library source described in the esaxx-rs paragraph below. Other path dependencies are the local Devboule workspace crates.

The design doctrine under `src/features/design/craft/` is adapted and original prose from three provenances. Nothing is copied: every section is condensed and rewritten, and each is capped at 2,500 characters by the loader's strict first-party check, so the ratio to any source cannot drift as the prose is edited. **From [refero_skill](https://github.com/referodesign/refero_skill)** (MIT, Copyright (c) 2026 Refero), `master` at commit a9b54a3e62a6391f5f5ab7a20e4ddb32fb79a27d taken on 2026-09-06, come the substance of `anti-ai-slop.md` and `color.md` and the rule structure of `typography.md`; `LICENSE.refero_skill` ships beside the material with the upstream MIT terms, and licenses that material rather than this directory. **From [OpenDesign](https://github.com/nexu-io/open-design)** at commit 3d0d15fc55031e8e6cead709491e7b82565c4dee, Apache-2.0, Copyright 2026 Open Design contributors, whose `craft/` is itself partly an adaptation of the same refero_skill material, come the whole of `state-coverage.md`; two rules in `anti-ai-slop.md`, against invented metrics and against filler copy; two in `color.md`, the mechanics of an undefined custom property, from `packages/contracts/src/design-systems/token-schema.ts`, and the cap of two visible accent uses per screen, which refero states only as "sparingly"; and the substance of `motion.md`, `rtl.md`, `form-validation.md` and `cognition.md`, condensed from their `animation-discipline.md`, `rtl-and-bidi.md`, `form-validation.md` and `laws-of-ux.md`. The last two were taken on 2026-09-07 and condensed to roughly a seventh of their upstream length (17,407 bytes to 2,396 characters of parsed body, and 17,635 to 2,315; the two sides are measured differently, so the ratio is an order of magnitude rather than a figure); `cognition.md` is renamed rather than tracking the upstream slug, because the section is organised around what the reader must do and not around the branded name of a rule collection. Those two upstream files carry no refero_skill attribution and appear original to OpenDesign, so they are credited to OpenDesign alone rather than swept under the blanket claim in the upstream's own README. OpenDesign is Apache-2.0, the same licence as this repository, so its terms are already in the root `LICENSE`. **From public standards and published design systems**, read directly rather than through either upstream, come the substance of `accessibility.md`, `spacing.md`, `layout.md`, `microcopy.md` and `icons.md`, and the citations in `typography.md`: success criteria and conformance levels from WCAG 2.2, and named guidance from Apple's Human Interface Guidelines, Material Design, IBM Carbon, GitHub Primer and the GOV.UK Design System. Neither upstream held usable material for spacing, layout, microcopy or icons. Where a figure comes from one design system rather than from a standard, the text says which, because a model reading these files would otherwise repeat a convention as a requirement. Every claim carrying a clause number or an attribution was verified against its primary source before shipping, and several inherited claims did not survive: an uppercase-tracking floor that upstream states as required rests on a Bringhurst passage about strings of small and full capitals, in which he writes that display capitals have no generalised optimum; an easing curve attributed to Material was wrong; and Arabic size and line-height ranges had no traceable source and were removed. The 2026-09-07 material was checked the same way and lost three claims. Two attributed form-validation practice to the ARIA Authoring Practices Guide: the APG has no form-validation or error-summary pattern prescribing where focus goes after submit, and its spinbutton example wires an invalid value with `aria-errormessage` rather than the `aria-describedby` recipe, so both attributions were replaced with the W3C WAI forms tutorial and technique ARIA21, and the surviving GOV.UK half was narrowed to what that design system actually does — it focuses the summary, and its examples do not use `aria-invalid` at all. The third was a dated citation to a paywalled commercial benchmark, which supported no rule a model could act on and could not be checked against a primary source, so it was deleted rather than hedged. The references to the upstreams' own linters and research tooling were dropped, and the rules name no palette, because the text guides code written into a user's project rather than into this one — concrete hex values appear only as values to avoid. `VERSION` records both origins with their commits and the date taken. The files are read as text and composed into a prompt; nothing in them is executed. This is prose rather than library source code, so the statement above still holds.

The daemon directly depends on `agent-client-protocol` 2.0.0 for the ACP
schema/protocol definitions. It is Apache-2.0 licensed; no source from that
crate is copied into this repository.

Third-party **sprite art** is a separate matter and is inventoried under Non-code assets below. It is carried by the Polis plugin rather than by the application, so an installation without Polis distributes none of it.

The esaxx-rs one-line CRT patch mentioned in the separate architecture document is present here. `crates/oracle-core` is a workspace member with an optional `fastembed` dependency, and the workspace root's `[patch.crates-io]` remaps `esaxx-rs` to the vendored `crates/oracle-core/vendor/esaxx-rs-0.1.10/` tree, which contains 1,047 Rust source lines. The crate's `Cargo.toml` declares Apache-2.0 and its `LICENSE` ships beside it. The patch makes esaxx-rs use dynamic CRT (`/MD`) on Windows, matching `ort-sys` prebuilt binaries; without it, the linker fails with `LNK2038` (`MT_StaticRelease` versus `MD_DynamicRelease`). Remove the patch when upstream esaxx-rs builds with the dynamic CRT on Windows, or when `tokenizers` stops depending on esaxx-rs.

The application does link/compile code from the registry dependencies listed below. In particular, rusqlite 0.40.2 is enabled with bundled: libsqlite3-sys 0.38.2 compiles the SQLite amalgamation it ships, SQLite 3.53.2, into the daemon artifact. That source is not checked into this repository, but it is part of the linked build input; rusqlite and libsqlite3-sys declare MIT, while the bundled SQLite amalgamation itself is distributed by SQLite under its public-domain dedication.
